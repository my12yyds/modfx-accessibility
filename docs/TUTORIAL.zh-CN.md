# 从 AI 辅助模组开发到视觉效果清单

这是一份可在本地复现的入门练习，不是游戏内模组开发教程。它演示如何把已实现的视觉效果控制选项转成清单并验证。

## 1. 安装并生成草稿

在仓库目录执行：

```sh
python -m pip install -e .
modfx-a11y init mymod.modfx.json --mod-id mymod
modfx-a11y lint mymod.modfx.json
```

生成器不会覆盖已有文件。父目录必须已存在；模组 ID 以小写字母开头，总长度不超过 64，后续可含小写字母、数字、下划线或连字符。

初始模板使用占位说明，所有控制项均为 `false`，因此会有一条建议警告。这是待填写的草稿，不代表已经实现任何游戏功能。

## 2. 对照真实代码填写

假设你的模组已经实现镜头晃动关闭选项：把 `id` 改成 `mymod:impact_shake`，描述效果何时触发，将 `controls.disable` 改为 `true`。没有实现的选项继续保留 `false`。

若实现强度调节，再把 `intensity` 改为 `true`，并在效果对象中加入：

```json
"intensity_range": {"minimum": 0, "maximum": 1, "default": 0.5}
```

默认值必须位于上下界之间。不要仅为消除警告而声明不存在的控制。

## 3. 请 AI 辅助审查

可以给助手这样的任务说明：

> 阅读本项目 SPEC.md 和我的视觉效果设置代码。列出实际已实现的控制及对应代码位置，再建议清单修改。无法确认的功能请明确说明，不要推断为已经实现。修改后运行校验和测试，并列出还需要游戏内验证的项目。

人工核对 AI 给出的代码位置、开关作用范围和默认值。不要把私人配置、访问令牌或他人未授权的源码加入示例。

## 4. 批量检查和回归测试

```sh
modfx-a11y lint examples/ --format json
python -m unittest discover -s tests -v
```

需要警告也阻止发布时再加入 `--strict`。成功校验不代表对光敏感玩家安全，也不能证明游戏运行时真的执行了设置。

## 5. 记录真实反馈

请记录模组版本、触发步骤、设置修改前后的表现和重启后的结果。欢迎提交最小清单与复现步骤，而不是只有成功截图。

更多背景见[社区分享资料](COMMUNITY.md)；其中视频属于维护者的其他开发实践，不是本项目已被视频中模组接入的证明。
